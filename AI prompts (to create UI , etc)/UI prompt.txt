بستر واقعی پیاده‌سازی
━━━━━━━━━━━━━━━━━━━━

این فروشگاه با ساختار زیر پیاده‌سازی خواهد شد:

- WordPress به‌عنوان سیستم مدیریت محتوا
- Hello Elementor به‌عنوان قالب پایه سایت
- Elementor برای طراحی و ساخت صفحات
- WooCommerce برای ساختار فروشگاه، محصولات، سبد خرید، سفارش و پرداخت

بنابراین تمام طراحی‌های UI باید با در نظر گرفتن قابلیت‌ها و ساختار واقعی Hello Elementor و Elementor انجام شوند.

طراحی نباید وابسته به قابلیت‌هایی باشد که پیاده‌سازی آن‌ها با این ساختار به‌صورت غیرمنطقی، پیچیده یا نیازمند توسعه اختصاصی گسترده باشد.

از طراحی‌هایی که صرفاً برای نمایش بصری جذاب هستند اما در Elementor قابل پیاده‌سازی واقعی نیستند خودداری کن.

در طراحی هر صفحه موارد زیر را در نظر بگیر:

- ساختارهای قابل پیاده‌سازی با Elementor
- استفاده منطقی از Container و Flexbox
- طراحی بخش‌ها به‌صورت Modular و قابل تکرار
- امکان ساخت Global Style برای رنگ‌ها، فونت‌ها و دکمه‌ها
- امکان ایجاد Header و Footer یکپارچه
- قابلیت Responsive برای Desktop، Tablet و Mobile
- سازگاری ساختار صفحات فروشگاهی با WooCommerce
- امکان استفاده مجدد از کارت‌ها، دکمه‌ها، Badgeها و سایر کامپوننت‌ها
- رعایت محدودیت‌های طبیعی یک سایت WordPress + Elementor

UI باید از ابتدا با رویکرد «طراحی برای پیاده‌سازی» انجام شود، نه صرفاً «طراحی برای نمایش».

سیستم کامپوننت‌های رابط کاربری

برای حفظ یکپارچگی طراحی، کامپوننت‌های اصلی سایت را به‌صورت یک Design System در نظر بگیر.

کامپوننت‌های پایه شامل:

- Header
- Navigation
- Footer
- Button
- Product Card
- Category Card
- Badge
- Input
- Search Box
- Filter
- Breadcrumb
- Pagination
- Modal
- Alert
- Tabs
- Accordion
- User Account Elements
- Shopping Cart Elements

هر کامپوننت باید از نظر:

- رنگ
- اندازه
- فاصله
- شعاع گوشه‌ها
- تایپوگرافی
- حالت Hover
- حالت Active
- حالت Disabled
- حالت Mobile

قابل تعریف و تکرار باشد.

در صفحات بعدی، در صورت استفاده مجدد از یک کامپوننت، همان ساختار بصری قبلی را حفظ کن.

هر طراحی باید به شکلی باشد که بتوانم آن را با Hello Elementor + Elementor + WooCommerce در یک پروژه واقعی پیاده‌سازی کنم؛ بنابراین بین زیبایی بصری و امکان اجرای واقعی، همیشه تعادل برقرار کن.
